# Linux test results

Test definitions, the record format and the criteria are in [test-plan.md](test-plan.md).

All values come from one unit. **Current status, 50 test IDs: pass 43, partial 4, fail 1, unverified 2** (the last
row of each ID in the main table).

| Term | Meaning |
|---|---|
| pass | Same as the expected result |
| partial | The part that can be measured was measured; the rest is open |
| unverified | Not tested yet, which is not a failure[^unverified] |
| measured | Read from logs, numbers or counters |
| observed | Seen, heard or felt on the device |

"Works" is said only of what was measured or observed. A driver that bound or a device node that exists is not
evidence.

[^unverified]: Image quality against the Windows Camera app (CAM-6) is not run yet. Hibernation (PWR-8) needs
    disk swap, which the tested configuration does not have.

How to read the tables:

- One row is one test run. A retest adds a row and keeps the earlier ones; **the last row for an ID is its current
  status.**
- Notes of a row from an unattended run say what is still open; "manual" marks what needs physical interaction or
  perception (the Kind column of [test-plan.md](test-plan.md)).
- The kernel column gives `uname -r` and, where it matters, which of this repository's patches were in it.
- The main table is NixOS with this repository's kernel. The packaged routes (linux-surface's kernel with `sp9-dkms`,
  [install.md](install.md)) on Ubuntu 26.04, Ubuntu 24.04, Debian 13 and Arch Linux were run once each and have their
  own tables at the end, not counted above.[^packaged-scope] Ubuntu 26.10 and Debian testing have no rows: they were
  built and install-tested in containers only.

[^packaged-scope]: Booted from an SD card in a USB card reader on the device, so they do not cover installing to the
    internal NVMe disk, dual boot next to Windows, disk encryption or standby power with the NVMe disk.
