# Linux test results

Test definitions, the record format and the criteria are in [test-plan.md](test-plan.md).

How to read the table:

- One row is one test run. When an ID is tested again a row is added and the earlier rows stay, so the same ID
  appears several times. **The last row for an ID is its current status.**
- Result: pass (same as the expected result) / partial / fail / unverified. Evidence: measured (logs, numbers,
  counters) / observed (a person saw, heard or felt it). "The driver bound" or "the device node exists" is not
  evidence that something works.
- Rows whose evidence is a measurement taken without a person at the device say in the notes what was measured
  and what is still open. "Needs a person" marks the part that only someone handling the device can decide.
- The kernel column gives `uname -r` and, where it matters, which of this repository's patches were in the
  running kernel.
- Current status by last row, 50 test IDs: pass 10, partial 20, fail 1, unverified 19.
- All values come from one unit.
